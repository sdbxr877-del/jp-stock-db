## 規範

引き継ぎ書（handoff）の読み手は、次セッションの開始時に**期待値と実測値を機械的に突き合わせる**。
書き手はそれを前提に、次の3点を守る。

### 1. 期待値には「照合の仕方」を添える

数値は**その時点のスナップショット**である。cron や外部要因で動く値を厳密一致で照合させると、
正常な増加が「異常」として検知され、セッションが不要に停止する（[[DB-48]]）。

| 値の性質 | 書き方 |
|---|---|
| 固定値（HEAD hash・ファイル数） | 厳密一致で照合してよい。そう明記する |
| 単調増加（行数・件数） | **「>= N（cron 稼働分は増加する）」**と範囲で書く |
| 未再測 | **「v82 未再測」と明示する**。書かないのが最悪 |

### 2. 推奨事項は「現状を確認したもの」だけ書く

「明日 `.gitignore` に `**/__pycache__/` を追記推奨」— 実際には既に登録済だった（[[DB-53]]）。
推奨を書く前に現物を読む。読んでいないなら「未確認: 〜を確認すること」と**タスクとして**書く。

### 3. 推奨手順には環境前提を明記する

`$PROFILE` 経由の恒久設定は ExecutionPolicy = Restricted 環境では機能しない（[[DB-52]]）。
手順を推奨するときは、**その手順が成立する前提条件**と、**前提を満たすかの確認コマンド**を併記する。

### 4. 期待値を無効にするときは「どれを・何に・なぜ」を書く

後から書いた文書が前の期待値を黙って上書きすると、次セッションは**古い値のまま機械照合して
「不一致 → 即報告 → 停止」で無駄に止まる**。差し替えるときは3点を明記する。

- 無効になる文書と項目を**名指しする**（「`handoff_db_v82.md` §6 の `rules 15` が無効」）
- 新しい値と、それが**実測値かどうか**
- 直さなかった場合に**何が起きるか**（照合で止まる／見逃す）

### 5. 変更にはロールバック手順を添える

戻し方が書かれていない変更は、問題が起きたときに戻せない。破壊的・不可逆な変更ほど必須。
「元ファイルは `_archive/` に `.bak` で退避」「この commit を revert すれば戻る」など、
**次の人がその文書だけ読んで戻せる**粒度で書く。

### 6. 波及範囲は「ゼロ」も明記し、根拠を添える

影響が無かったことを書かないと、**調べてゼロなのか調べていないのかが区別できない**。

| 書き方 | 意味 |
|---|---|
| 波及: ゼロ（論証で確定） | 調べた結果、影響が無いと確定した |
| 波及: 9件（実測） | 調べて9件と確定した |
| 波及: 未調査 | まだ調べていない（**これも書く**） |

### 7. 棄却した案・持ち越した項目を記録に残す

- **棄却案は「棄却」と分かる形で残す。** 書かないと、次セッションが同じ案を再検討して
  同じ結論に辿り着くまでの時間を丸ごと払い直す
- **持ち越しは回数を連ねて書く。** 「未着手」ではなく「v77 → v78 → v79 でも未着手」。
  何回先送りしたかが見出しに出ていれば放置に気づける。消化したら「全消化」と書いて閉じる

## 違反パターン(検出すべき記述)

### Pattern 1: 動く値を厳密一致で書く
```markdown
<!-- 違反例 -->
| 総件数 | 4,934,612 | 一致すること |
```

### Pattern 2: 現状未確認の推奨
```markdown
<!-- 違反例 -->
- 明日 `.gitignore` に `**/__pycache__/` を追記推奨
```

### Pattern 3: 前提条件のない手順推奨
```markdown
<!-- 違反例 -->
- 案A: $PROFILE に環境変数を書いて永続化する（推奨）
```

### Pattern 4: 前の期待値を黙って上書きする
```markdown
<!-- 違反例: v82 では 15 だったが、どこにも「15 は無効」と書かれていない -->
| `rules` | 20 |
```

### Pattern 5: 影響が無いことを書かない
```markdown
<!-- 違反例: 波及の記載が無い。調べたのか調べていないのか読み手には分からない -->
- `01_daily_metrics.sql` の base CTE を修正した
```

## 正しい記述パターン

```markdown
<!-- ✅ 照合方法を添える -->
| 項目 | 期待値 | 照合 |
|---|---|---|
| HEAD | `80451f7...` | 厳密一致 |
| `raw.prices` 総件数 | **>= 4,934,612**（v82 時点。平日 cron で増加） | 下限照合 |
| tracked ファイル数 | 91 | **v82 未再測**（commit 後の `git ls-files` 未実行） |

<!-- ✅ 現状確認済みの推奨 / 未確認はタスクとして -->
- `.gitignore`: `__pycache__/` は **:5 に登録済（確認済）**。追加対応不要
- 未確認: `**/__pycache__/` 形式にすべきかは未検証。次セッションで判断すること

<!-- ✅ 前提条件と確認コマンドを併記 -->
- 案A: `$PROFILE` 経由で永続化
  - **前提**: ExecutionPolicy が RemoteSigned 以上
  - **確認**: `Get-ExecutionPolicy -Scope CurrentUser`（Restricted なら案A は不可・案B へ）
```

```markdown
<!-- ✅ 期待値の差し替えは「どれを・何に・なぜ」 -->
**`handoff_db_v82.md` §6 の期待値のうち `rules 15` が無効**（本補足で 20 に更新・実測値）。
次セッションの §C では 20 で照合すること。15 のままだと「不一致 → 停止」で無駄に止まる。

<!-- ✅ 変更にはロールバックを添える -->
- 変更: `01_daily_metrics.sql` に flag / clean CTE を新設
- ロールバック: この commit を revert すれば戻る（`.bak` は `_archive/` にも退避済）
- 波及: `screening_candidates` へ **ゼロ（論証で確定）**

<!-- ✅ 棄却・持ち越しを残す -->
- 候補2 `07` の pick 化 → **棄却**（理由: universe flip が未解明のため効果が測れない）
- ナレッジ更新: v77 → v78 → v79 → **v80 でも未着手**
```
